# Session 24 — 2026-10-10 : SASL contre un vrai QEMU, issue #32

## Serveur
QEMU 10.2.1 (`qemu-system-x86_64 -display none -vnc 127.0.0.1:N,sasl=on`),
Cyrus SASL avec le fichier `qemu.conf` pointé par `SASL_CONF_PATH`
(`mech_list`, `sasldb_path`) et un utilisateur créé avec `saslpasswd2 -a qemu`.

## Ce que QEMU propose réellement
D'après `ui/vnc-auth-sasl.c` et ce qu'on observe :
- **SASL seul (type 20)** : `min_ssf=56`, `NOPLAINTEXT` et `NOANONYMOUS`.
  Avec `mech_list: plain`, la liste est vide et QEMU ferme la connexion
  (trace « no available SASL mechanisms »). Avec `digest-md5 plain`, il ne
  propose que `DIGEST-MD5`.
- **VeNCrypt TLSSASL (264, TLS anonyme)** : mêmes contraintes, donc PLAIN est
  aussi retiré. De plus, sans `dh-params.pem` dans le dossier de
  `tls-creds-anon`, GnuTLS 3.8.12 refuse la poignée de main TLS
  (« Insufficient credentials »).
- **VeNCrypt X509SASL (263, certificat)** : `min_ssf=0`, donc PLAIN est
  proposé. C'est le seul chemin utilisable avec PLAIN.

## Changements
- `_VENCRYPT_X509_SASL = 263` et `_VENCRYPT_TLS_SASL = 264`, placés dans l'ordre
  de préférence juste après les sous-types Plain de chaque famille. La
  négociation SASL existante (`_sasl_negotiate`) passe sur le flux TLS.
- Fermeture avant la liste des mécanismes : `ConnectionError` avec un
  message explicite (avant : `IncompleteReadError`).
- Fermeture après l'envoi de PLAIN, c'est-à-dire la façon dont QEMU refuse :
  `PermissionError`.

## Résultats
`test_live_qemu_sasl.py`, 7 tests, tous verts :
- X509SASL avec PLAIN : connexion en 3.8 et capture réussies ;
- mauvais mot de passe et utilisateur inconnu : `PermissionError` ;
- CA non reconnue : `SSLCertVerificationError` ;
- SASL seul avec PLAIN : `ConnectionError` ; avec DIGEST-MD5 seul :
  `ValueError` ;
- TLSSASL anonyme : `ConnectionError`.

Note : la CA de test doit porter `keyUsage` (exigé par Python ≥ 3.13).

## Limites
- ANONYMOUS n'est jamais proposé par QEMU, donc pas vérifié contre un serveur
  réel.
- DIGEST-MD5, GSSAPI et SCRAM restent hors périmètre (#25).
